# 机械守卫

`pnpm check` 依次执行生成源校验、源码与消费者类型检查、lint、格式、带分包覆盖率的行为测试、未使用代码分析、循环依赖分析、责任边界检查、生产构建、发行声明面检查、打包产物的 Node 与浏览器消费验证和文档构建。

发行类型检查通过 NodeNext 解析包的公开导出。类型用例直接引用工作区实现时，TypeScript 项目边界检查会失败。

首次执行消费者门禁前，运行 `pnpm exec playwright install` 安装锁定版本对应的浏览器；Linux CI 使用 `pnpm exec playwright install --with-deps` 同时安装系统依赖。Playwright 升级后需要重新安装对应浏览器。

浏览器消费者从受检 tarball 构建，在 Chromium、Firefox、WebKit 中实际执行，分别检查运行时默认环境和原生 disposal Symbol 缺失的环境。用例覆盖原生取消状态、事件传播被停止时的取消、订阅解除、观察资源替换、Platform 激活与 Host 清理。消费代码使用导出的释放 key，不依赖 `using` 转译器安装全局 Symbol。构建目标仍由运行版本策略定义，实际浏览器测试报告其使用的内核，不把当前内核测试等同于所有历史最低版本均已执行。

## 架构规则

| 规则 | 含义 |
| --- | --- |
| `ownership.package` | 每个源码包必须声明责任 |
| `ownership.module` | 生产源码必须属于已声明职责，不能依赖工作区测试、工具或其他非生产目录 |
| `direction.package` | 包依赖只能沿声明方向 |
| `direction.module` | 低层不得导入高层责任 |
| `types.suppressions` | 禁止静默禁用类型检查 |
| `types.precise` | 禁止显式 any |
| `callbacks.readonly` | Port 与 Control 使用只读函数属性 |
| `tests.types` | 编译期断言归 public-api.types.ts |
| `runtime.portable` | 运行库的 ESM 导入、import-equals 和全局 CommonJS `require` 均禁止依赖 Node 内建模块 |
| `exports.public` | 跨包只使用正式公开入口 |
| `modules.esm` | 相对源码导入具有显式运行时扩展名，发行类型支持 NodeNext |
| `reactive.independent` | reactive 保持零外部依赖 |
| `vocabulary.current` | 在运行库与公开 API 中检查退休词汇；运行库、examples 与 tooling 的项目自有生产声明须使用完整名称 |
| `logging.port` | 库日志由 Logger 端口控制 |
| `policy.explicit` | 库策略不读取环境时钟或随机数 |
| `lifetime.owner` | Lifetime 根仅由执行层或既有树创建 |
| `contracts.owner` | 固定 Contract ID 只有一个定义所有者 |

词汇规则保留外部 API 的原始导入名和工具协议字段；项目自行声明的别名仍须使用完整名称。测试及测试夹具不计入生产声明。

行为测试覆盖原子发布、计划权限、恢复与隔离、生命周期义务、取消、跨副本信号与隔离的打包消费者。门禁变异测试证明非法依赖方向确实失败。API 守卫检查包含纯类型导出的发行声明面，要求中英文记录所有导出和错误码，并按真实 Markdown 文件校验导航。协议生成文件只有 `tooling/internal` 中一个源所有者，修改源后重新生成。

架构守卫从 TypeScript 符号识别契约工厂；别名与命名空间导入仍指向同一个定义。通过常量或只读属性传入的固定 ID 也要参与相同的冲突检查。跨包入口和运行时目标从实际解析的模块和包的 `exports` 检查，覆盖再导出、字面量动态导入和导入类型。发布前还要验证 tarball 具有每个公开入口的 JavaScript 和类型文件，包括 `dougong/advanced`。

Core 与 Platform 的内建错误协议值分别只在所属的 `contracts/errors.ts`、`errors.ts` 中通过具名常量定义。`PlatformErrorCode` 从这些常量推导，各调用点引用同一份定义。守卫解析真实错误构造符号与错误码类型，核对错误参考页表格的目录投影；导入别名、条件表达式和派生错误仍指向同一协议定义。其他页面用指向该参考页的 Markdown 链接标明错误引用，例如 [`HOST_BUSY`](./errors.md)。守卫检查这些链接、代码示例中的框架错误构造，以及目录完整性。普通 `HTTP`、`HEAD` 等技术术语和应用自己的 code 字段不属于错误码域。

运行版本范围由 `tooling/runtime-baseline.mjs` 定义。修改策略后运行 `pnpm generate:runtime`，统一生成包清单的运行约束和文档中标记的 Node、浏览器版本片段；`pnpm check:generated` 与 API 守卫使用同一个派生实现检查漂移。文档其余解释保持手写，标记缺失或重复会明确失败。CI 直接从该策略读取最低版本和当前分支矩阵。Node 与浏览器使用同一份公开取消组合实现，不再依赖 Node 内部监听选项。

文档守卫通过 VitePress 解析生效的导航配置和 Markdown，通过 Vitest 解析实际覆盖率配置。错误码、退休词汇、公开导出和表格检查共享每份文档的一次解析结果；引用式链接、较长的合法闭合围栏和小数阈值都按实际语义处理。未使用的导航 helper 不能冒充生效的 sidebar，等价的阈值表达式不会被当成漂移。

公开 API 的预期清单只在 `tooling/architecture/public-api.json` 中维护。源码测试、发行声明及四个真实 ESM 入口都对照这份清单检查。

发布自动化支持 Linux 和 macOS，要求按仓库声明的版本安装 Node 与 pnpm，并让 Git 2.48 或更新版本、npm、pnpm 可执行文件直接出现在 PATH 中。Git 版本在源检查、清单写入及上传前验证；旧版本的引用事务钩子不会只报告实际目标更新，不符合发布记录的授权协议，不能继续发布。其他操作系统会在工作区检查前拒绝。包管理器直接启动，不经过 shell。上传步骤继承真实终端，让 npm 可以完成网页二次验证；注册表查询仍捕获输出并保留进程组截止期限。交互回归测试使用系统的 `script` 命令创建伪终端；它不是 npm 依赖，列在 Knip 的系统命令清单中。

发布时先设置目标版本，再运行完整门禁。消费者测试与发布使用同一组归档：隔离应用通过后，消费者才记录归档哈希。其余检查完成后，发布端核对哈希、源清单、本次实际获取的远端提交及远端标签，然后才允许首次上传。发布锁定 `origin` 配置的唯一推送地址，并确认其 main 指向本次获取的提交。读取引用和推送使用同一个命令级 remote，其 `url` 与 `pushurl` 相同，不修改持久配置；若 `insteadOf` 仍会再次改写已捕获的地址，则在上传前拒绝。每次上传前重新核对该地址的分支和标签，最终向同一地址推送；记录 Git 版本时以预检得到的远端引用为条件。已存在的版本和首次上传的版本，都必须从注册表读回，逐文件核对后才记录 Git。

预检先捕获本地源提交的 SHA，再用这一不可变值检查领先、落后和发布恢复条件。清单写入前、每次上传前及记录发布前，都确认工作区仍指向该源提交。如果其他操作移动了分支，发布会终止并保留对方的提交，不把旧来源的检查结果用于新的源提交，也不擅自回滚分支。

发布提交在私有索引中基于捕获的源提交构造，parent 明确绑定该 SHA。Git 的 clean filter 和行尾转换仍参与清单入库，转换后的提交必须再次通过版本与文件集合校验。提交构造不运行工作区的 commit 或 index hooks。真正更新引用时，使用命令级私有 `reference-transaction` 钩子；Git 持有 `HEAD` 及其实际目标的锁之后，只允许已验证的 `refs/heads/main` 从预期源 SHA 变为已验证提交。即使另一分支与原 main 指向相同 SHA，也不能承接这个更新。钩子源码在发布模块加载时捕获，执行副本与只读证明存放于私有目录，并使用当前 Node 进程对应的解释器。

记录期间持有标准 `index.lock`，保留其他文件已有的暂存内容，只用已验证提交中的清单条目更新原索引，不写工作树。已存在的索引锁不会被替换或删除。索引锁保护索引写入，引用事务保护实际目标授权；两者不把多个并发 Git 命令合成一个工作区事务。

引用命令结束后按明确的 main 引用核对结果。命令失败且 main 仍为原源提交时，丢弃本次索引投影，由既有来源守卫决定是否恢复清单。main 已记录发布提交且工作区仍指向 main 时，完成索引投影；即使命令回执失败，也保留已经完成的提交以供原版本重试。无法读回、引用已被推进到其他提交或工作区已经切换时，不再写索引或自动恢复旧清单；保留准备好的索引并报告引用、原 SHA、发布 SHA 和保留路径。必须先检查 Git 状态并处理保留的索引，再恢复发布。

每个包在一次发布中固定使用一个注册表。解析遵循 npm 的优先级：包 scope 的专用注册表、配置 scope 的专用注册表、默认注册表；`publishConfig` 覆盖同名 npm 配置项。`publishConfig.registry` 只覆盖默认注册表，已有的 scope 专用地址仍优先。身份验证、版本及渠道检查、上传和包内容回读都固定使用解析后的同一地址。注册表凭证通过 npm 单独配置。

每个发布清单都明确列出需要分发的文件或目录（使用字面路径）。打包必须保留这些文件，包括 `dist/` 之外声明的资源；不能额外引入其他文件或元数据。工作区依赖按受检版本解析，包管理器专用字段和打包生命周期脚本可以不进入产物。ESM 构建从各包的清单推导外部依赖及其子路径。声明检查根据 TypeScript 的模块命名空间区分真正可用的构造器和仅作类型再导出的类。

稳定版和预发布都必须为每个包明确指定 npm 分发标签。稳定版可执行 `pnpm release 0.7.2 --tag=latest --dry-run`，预发布可执行 `pnpm release 0.7.2-alpha.1 --tag=next --dry-run`；检查通过后去掉 `--dry-run` 发布。命令行标签覆盖各包的 `publishConfig.tag`；未提供命令行标签时，每个包都必须声明 `publishConfig.tag`，不采用 npm 配置中的默认 tag。缺失或非法渠道在任何 Git/npm 命令及清单写入前拒绝。标签以 ASCII 字母或数字开头，后续可包含字母、数字、点、下划线和连字符，并须与 SemVer 范围明确区分。发布输入捕获后，每个包的上传、恢复核验和最终渠道确认都使用同一标签。部分上传后使用相同的标签恢复；在创建远端 Git 标签前，归档内容和每个渠道的目标版本都必须匹配。远端 Git 标签已经记录的历史版本允许 npm 渠道继续前进。

发布会话异步执行 Git、npm 和 pnpm 命令，检查与上传期间也能接收 `SIGINT`、`SIGTERM` 和 `SIGHUP`。每个命令拥有独立的 POSIX 进程组。上传继承真实终端描述符，其他命令通过会话持有的管道转发或捕获输出。首次取消向进程组转发原信号，并开始两秒的协作退出宽限期；再次中断或宽限期届满时，向进程组发送 `SIGKILL`。未收到取消时，认证等待没有截止期限。

取消会阻止后续上传和 Git 记录。在恢复清单或移除归档前，会话先等待命令退出及共享输出关闭，再确认进程组已经不存在。交互命令的主进程退出不能证明其后代已经停止。如果强制终止并经过有界确认等待后仍无法确认进程组退出，则报告组标识并保留 stage 和清单供检查；必须先确认该组退出，再修改这些文件。会话最后以首次收到的信号终止。该边界不管理主动脱离命令进程组的后台进程。

引用更新开始前仍会拒绝已经发生的取消。进入短暂的引用记录步骤后，取消（包括再次收到信号）须等待 Git 结算、已提交清单的恢复义务解除以及索引投影完成；结果无法确认时则保留待检查索引。完成这些收尾后再传播原信号，之后不会创建标签或推送。这样不会因命令已经提交但取消先被观察到，而丢弃尚未完成的索引投影。

正常失败与取消共用清理入口。原始失败和清理失败均会报告，清理失败不会改写终止信号、覆盖其他操作的清单或自动重试已经放弃的恢复义务。上传被中断时，注册表结果未知，已经上传的不可变 npm 版本仍会保留。使用原版本与原渠道重新执行时，会先核验注册表再决定是否上传。已经完成的 Git 提交由 Git 的实际状态决定恢复方式。成功完成的 dry run 也会保留归档目录供检查。

发布被 npm 接受之后，注册表可见性查询和 Node 原生异步计时等待共用一个单调时钟截止期限。每次等待取轮询间隔与剩余预算的较小值；慢查询或等待不能刷新截止期限。每次查询只获得剩余预算，由会话在超时后强制终止查询进程组；即使主进程已经正常退出，只要共享输出尚未关闭，截止期限仍然有效且超时必须报告失败。慢查询及其普通后代不能延长总等待。只有明确的 E404 表示版本尚不可见，认证、网络、格式或查询超时失败都终止观察，不能被当成成功发布。
